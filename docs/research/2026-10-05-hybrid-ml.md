# V7 workstation research and evidence protocol — October 5, 2026

This implements two bounded offline weather challengers on the workstation and
keeps AWS responsible for durable collection, forecasts, paper execution and
publication. It does not authorize real-money execution, promote a model, resize
AWS, buy a service or claim profitability. The dated export is evidence of what
AWS had recorded at its capture time; it is not a fresh operational check.

## Why these methods

WeatherEdge already has inverse-error-variance EMOS and a trailing, shrunk,
deadbanded bias correction. Reimplementing EMOS and comparing only against a raw
ensemble would exaggerate new value. The new evaluator compares every arm on the
same station, lead and target cases against both existing raw EMOS and the
existing bias-only correction, with the latter as the primary comparator.

[Gneiting, Raftery, Westveld and Goldman, minimum-CRPS EMOS](https://stat.uw.edu/research/preprints/tech-report/calibrated-probabilistic-forecasting-using-ensemble-model-output)
provides a well-established probabilistic temperature postprocessing approach.
The new **minimum-CRPS location/scale challenger** learns a bounded residual mean
shift and multiplicative uncertainty adjustment for each station and lead. It
minimizes Gaussian CRPS on strictly earlier training targets, then shrinks toward
the existing corrected distribution. This is a small calibration extension to
the current EMOS distribution, not a new numerical weather model or a claim to
reproduce the paper's complete member-level regression.

The **gradient-boosted quantile challenger** is a substantive nonlinear learner
implemented with the workstation's existing scikit-learn installation. It learns
three residual quantiles, adds them to the existing corrected forecast, and
conditions on corrected mean, uncertainty, model spread, member count, explicit
missingness, seasonal sine/cosine and station indicators. Stations are categories,
not ordered numeric measurements. It uses the official estimator and
[scikit-learn's quantile prediction-interval example](https://scikit-learn.org/stable/auto_examples/ensemble/plot_gradient_boosting_quantile.html),
following the loss-based tree-boosting framework in
[Friedman, *Annals of Statistics* (2001)](https://doi.org/10.1214/aos/1013203451).
Separate quantiles can cross; deterministic sorting corrects their order without
consulting the target outcome, and the crossing count is retained. Three
quantiles do not specify an entire CDF. This arm reports pinball loss, median MAE,
90% interval coverage, width and interval score; it does **not** invent Gaussian
CRPS or executable prediction-market bucket probabilities.

[NGBoost, ICML/PMLR (2020)](https://proceedings.mlr.press/v119/duan20a.html) and its
[Stanford group's Apache-2.0 implementation](https://github.com/stanfordmlgroup/ngboost)
were reviewed as a future full-distribution boosting alternative. NGBoost learns
distribution parameters through natural-gradient boosting. It is not installed
or silently substituted for the implemented quantile learner. The existing
quantile estimator lets us implement and test nonlinear uncertainty research
without dependency installation or heavier production infrastructure.

[Adaptive conformal inference, NeurIPS (2021)](https://proceedings.neurips.cc/paper/2021/hash/0d441de75945e5acbc865406fc9a2559-Abstract.html)
is a credible future interval-calibration wrapper under changing distributions.
Its long-run coverage result is not a conditional guarantee for every city/day,
and calibrated intervals alone do not prove bucket prices or trading profit.
It was reviewed, not implemented or represented as an achieved guarantee.

## Fixed experiment and resource choices

The new script is `scripts/evaluate_v7_ml.py`; regression checks are in
`trading/tests/test_v7_ml.py`. Gaussian calibration uses only the standard library.
Boosting is explicitly optional with `--with-boosting`, using already-installed
scikit-learn 1.9.0 in `.venv-dev`. No model library is installed on AWS.

Before the first dataset run, these choices were fixed:

| Choice | Value and rationale |
|---|---|
| Baseline correction | Existing 45-day bias-only policy, existing shrinkage and deadband |
| Baseline eligibility | All 45 earlier calendar targets must be available in that station/lead window |
| Challenger fit window | Last 90 calendar days; at least 45 distinct targets per station/lead |
| Forward fit blocks | 28 calendar target days; freeze each fit before its first simulated serve |
| Location grid | −1.5, −1, −0.5, 0, 0.5, 1, 1.5°F |
| Scale grid | 0.75, 0.875, 1, 1.125, 1.25, 1.5 |
| Shrinkage | 30 pseudo-dates toward zero location shift and unit scale |
| Common Gaussian floor | 1.5°F, the existing scoring floor, applied consistently to all Gaussian arms |
| Quantiles | 0.05, 0.5, 0.95; directly evaluate a central 90% interval |
| Boosting per quantile | 24 trees, depth 2, minimum 30 rows per leaf, learning rate 0.05 |
| Random seed | 20261005 |
| Uncertainty diagnostics | 1,000 paired seven-calendar-day moving-block resamples; whole dates retain all station/lead observations |
| Input cap | 100 MB JSON; 250,000 rows per table; truncation is an error |
| Run cap | 300 seconds, one numerical-library thread; workstation worker adds AC/thermal/load, memory and duty-cycle guards |

These hyperparameters are transparent regularization and compute-budget choices.
The cited research supports the methods, not the claim that these numbers are
optimal for WeatherEdge. No holdout-driven parameter search, random train/test
split, test-set early stopping or automated winning-model promotion occurs.
Keeping fixed imperfect candidates also gives us falsifiable negative results.

## Temporal and evidence boundaries

Only `rolling_origin_v2` rows with canonical `emos_wmean`, registered stations,
lead 1 or 2, finite distributions, completed station climate days and matched
official **final** CLI truth enter the retrospective experiment. The cached
`actual_high_f` field is ignored. Duplicate station/lead/target rows, duplicate
final truth, future capture clocks and truncated exports fail closed. Older
sources, unknown stations and other methods do not mix into training.

For each fit, training truth targets are strictly before the first simulated
serve date. Each historical baseline correction also uses only earlier targets.
Training never includes a target merely because it precedes the test target:
lead time is respected. Every fold retains its cutoff, latest training target,
station counts, training digest, fitted parameters and actual retrieval-clock
availability count. Each compressed prediction record links to that fold.

**Target-date ordering is necessary but insufficient.** The reconstructed export
was recorded after many nominal serve times. It cannot establish original
provider initialization, complete constituent hours or truth availability at a
historical decision. Thus the report has two separate scopes: retrospective
weather diagnostics and strict original-vintage eligibility. The latter remains
zero for reconstructed rows, even if an individual storage clock looks early.
New append-only served/member tables must stay separate; their presence does not
retroactively upgrade the reconstructed cohort or establish strategy profit.

Every comparison uses identical cases across included arms. We retain individual
station/lead results and per-date counts, plus case-weighted and date-equal
averages. Seven-day blocks never bridge a missing calendar day. Approximate
bootstrap intervals are exploratory because this archive and previous policies
were already inspected, arms are multiple comparisons, and rolling training
windows overlap. Case counts are not independent observations. A favorable
pooled score cannot hide a harmed flagship station or justify a city rollout.
If any reported date lacks support in a complete seven-day block, the interval
is unavailable rather than silently dropping that date from resampling.

The evaluator also scores optional actual `forecast_emos_live_vintages` and
`nwp_live_forecast_members` exports in a **separate as-issued weather population**.
It verifies the content-addressed snapshot/member identity, station settlement
window, actual lead, source and retrieval-before-recording clock, prior training
target, finite distribution and final truth after the completed target day.
Within each producer/model identity, it chooses the earliest valid issue per station, target and actual lead using
observed clocks, without selecting by realized error. Missing tables and deployed
but empty tables are different report states. Intraday repeats do not create
extra independent days. Provider initialization and complete member hour counts
may still be NULL; the report keeps them unknown while scoring the actual
received daily-max distribution. This separate population scores the **exact
stored issued sigma**, including a valid sub-1.5°F sigma, without silently
replacing it with the retrospective comparison's scoring floor. A training digest does not prove individual
truth-availability receipts or a preregistered policy. This population can grow
when V7 collection is deployed, but cannot turn the two challengers fitted now
into forecasts issued in the past or establish live-money eligibility.
Optional hashed `shadow_forecast_lineage` links snapshots to the workstation's
`local-shadow-v7-v1` identity and model/policy fingerprint. Such cases are labeled
`local_shadow`, never described as the installed AWS V7 service. Without producer
metadata the producer identity remains unestablished rather than being inferred.
Different producer/model identities retain separate score summaries; even matched
station-days across those identities are shared outcomes, not independent days.

## Reproduction and retained results

Use a captured, bounded AWS weather export in private local state:

```bash
nice -n 15 .venv-dev/bin/python scripts/evaluate_v7_ml.py \
  --export .local/v7-audit/weather-export.json \
  --output docs/research/2026-10-05-hybrid-ml.json \
  --lineage-output docs/research/2026-10-05-hybrid-ml.lineage.jsonl.gz \
  --with-boosting
.venv-dev/bin/python -m pytest -q trading/tests/test_v7_ml.py
```

The JSON and compressed JSON-lines artifact retain source-export and
implementation SHA-256 hashes, all fold parameters, all paired scores and
station/date lineage. They contain no account identities, credentials, private
access paths or bankroll assertions. The raw export remains ignored operator
state. A new run must write a new run directory and retain the preceding
successful receipt on budget, thermal or source-validation failure.

The accompanying generated JSON is the authoritative numerical result. Its
`retrospective` section compares the fixed candidates; `strict_prequential`
discloses why these are not issued V7 forecasts; `capital_gate` remains blocked.
The September 5 ML experiment and October 5 bias-only evidence remain separate
historical research and are not relabeled as V7 trading performance.

The completed experiment reused the AWS export captured **October 5 at 20:35 PDT**
(`2026-10-06T03:35:08.942265+00:00`). It scored **6,656 paired station/lead targets
over 246 calendar dates, January 15–September 17, 2026**, using eighteen frozen
lead-specific forward rounds. The baseline-history and prior-training eligibility
rules exclude later or earlier cases without the required history; this period
is not claimed as full live coverage through the capture date.

**Neither new candidate established improvement over the existing bias-only

[+0.00263, +0.02440]°F. Boosting's mean pinball and interval score are also worse;

promotion, not a reason to tune on the same test outcomes until a winner appears.
Both candidates remain implemented for separately preregistered future research;
serving probabilities and trading controls are unchanged. Strict original-vintage
cases are **zero**, so even a favorable score would not prove prospective V7 edge.

## Profitable-process and capital decision

The current evidence supports **$0 authorized live allocation** and no justified
initial live bankroll recommendation. That is a research authorization result,
not an estimate that a particular bankroll is optimal. Weather CRPS, win rate,
paper account starting balances and a desired daily dollar profit cannot solve
capital sizing. Market prices, actually filled size, fees, depth, quote age,
slippage, concurrent-city dependence, calibration uncertainty and a tolerable
loss distribution are required inputs.

[Busseti, Ryu and Boyd's risk-constrained Kelly research](https://web.stanford.edu/~boyd/papers/kelly.html)
provides a principled growth/drawdown formulation under a specified outcome
distribution. Its guarantee relies on that distribution and constraints; it
does not determine optimal dollar capital or validate WeatherEdge's edge.
After independent prospective fills support a positive net edge, model joint
day-level returns and evaluate capital versus drawdown, liquidity and capacity
under explicit stress assumptions. Retain adverse and zero/outage days. Report
uncertainty across economically separate strategy accounts rather than summing
them into a fictional portfolio. Proposed quantitative risk limits are selected
as declared research assumptions; actual real-money enablement still requires
the user's explicit authorization.

`capital_frontier()` implements this research step without changing live budgets.
It requires at least thirty complete consecutive prospective calendar days under
a verified identity, verified nominal fills and observed peak open cost, and
cost-inclusive net P&L plus gross realized losing slices. Profitable closes do not
erase intraday realized losses. Seven-day joint date-block resamples estimate a daily
net-P&L lower bound and the distribution of wealth paths. A nonpositive lower
bound blocks the study. The declared candidate limits are 1% daily realized loss,
5% peak open cost, 10% maximum drawdown, and at most 5% empirical risk-budget or
drawdown breaches. These conservative research choices are **not paper-derived
optimal constants or guaranteed future bounds**, and do not alter existing
production risk controls. The helper derives a starting capital bound from
observed exposure/loss budgets and examines seven bounded capital multiples,
without scaling assumed fills, liquidity or earnings with bankroll. It reports
the smallest empirically feasible capital for **the same observed nominal fill
sizes**, a feasible study range and its assumptions. This is a capital-efficiency
study, not a globally optimal investment recommendation. Its conservative daily
drawdown envelope places realized losing slices before gains and regards observed
peak open cost as fully at risk; it does not invent exact intraday trade order.
With today's missing
independent net-fill evidence the output remains null and live allocation $0.
The input contract requires an exact verified boolean, an explicit timezone-aware
as-of clock, an explicit calendar timezone, and every day completed before that
clock. All rows must identify the same economic account and the same valid
strategy/policy SHA-256 fingerprint. Future/partial days, missing lineage and
mixed accounts or fingerprints fail closed. Private account keys are used only
for input consistency and never copied into the generated study report.

The falsifiable process is: immutable V7 forecast and policy identity → available
issued inputs and correct final station truth → prospective calibration and
station-level improvement → dated executable quotes and realistic paper fills →
net filled P&L confidence bound and drawdown/capacity analysis → operational
readiness and explicit user authorization. Failed stages keep subsequent stages
blocked. No allocation, model promotion or live-order flag is automatically
changed by the workstation researcher.
